# The audit trail

**`%%auditPath%%`**, under *System*. Every create, update, delete and restore,
with who did it, when, from which address, and both sides of every value that
moved.

## Reading an entry

The list shows the record, what happened to it, and who. Open one and you get a
before-and-after table: only the fields that actually changed, old value beside
new value.

Filter by module, by action, by person, or by date range. Filters live in the
address, so a link to "everything Aisha deleted last week" is shareable.

## What is not recorded

| Left out | Why |
|---|---|
| Passwords, tokens, secrets | Written as `••••••••`. That a password *changed* is exactly what an audit trail should show; what it changed to is not |
| `updated_at` | It changes on every save and tells you nothing the timestamp does not |
| `deleted_at` | Restoring a record fires both an update and a restore; without this the same event would be logged twice |

## Putting your own model on it

Models generated by `isproject:crud` are already auditable. For a model you wrote
by hand, add the trait:

```php
use IsProject\Framework\Concerns\Auditable;

class Book extends Model
{
    use Auditable;
}
```

That is the whole change. Creates, updates and deletes are recorded from then on.

## Turning it off for one operation

Bulk imports and seeders would otherwise write one audit row per record, which
buries the changes people actually made:

```php
app(\IsProject\Framework\Support\AuditRecorder::class)->withoutAuditing(function () {
    Book::factory()->count(500)->create();
});
```

## Keeping it from growing forever

An audit trail grows with every save and never shrinks on its own. Prune it:

```bash
php artisan isproject:audit-prune --days=90 --pretend   # count what would go
php artisan isproject:audit-prune                       # use the configured retention
```

Scheduled, in `routes/console.php`:

```php
Schedule::command('isproject:audit-prune')->daily();
```

> [!IMPORTANT]
> Auditing never breaks a save. If writing the audit row fails — the table is
> missing, the disk is full — the error is reported and your record still saves.
> An audit trail that can take down the thing it is watching is worse than no
> audit trail.
