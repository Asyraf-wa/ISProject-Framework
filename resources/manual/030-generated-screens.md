# The generated screens

Every module generated by `isproject:crud` gets the same five screens. Learn them
once and you know all of them.

## The list

`/books` — the screen you land on. It has:

**A search box.** It looks across the text columns of the table, so typing a
title or an author narrows the list. The search survives paging and sorting: it
is part of the address, so the link is shareable.

**Sortable headings.** Click a column heading to sort by it; click again to
reverse. An arrow shows which column is in charge. Columns backed by a related
table sort by the name you see, not by the hidden id, so a category column sorts
alphabetically rather than by whichever category happened to be created first.

> [!NOTE]
> Only columns the generator whitelisted can be sorted. This is deliberate:
> the sort column goes into the SQL, so a made-up column name in the address is
> ignored rather than obeyed.

**A page size.** 20, 30, 40, 50 or **All**. It is remembered in the address like
everything else. *All* is capped, so a table with a hundred thousand rows will
not take the page down.

**A row menu.** The three dots at the end of each row: view, edit, archive or
delete. It opens above everything else, including inside a table that scrolls
sideways.

## Create and edit

The form is full width and split in two: the fields on the left, and a panel on
the right explaining what is required and why. Required fields carry a red mark.

If something is refused, the page comes back with the offending fields outlined
and a message under each one. What you typed is still there.

### Dropdowns you can type into

A dropdown with more than eight choices — a category list, a timezone, a route
name — lets you type to narrow it instead of scrolling. Click it and start
typing; the arrow keys and Enter pick from what is left.

Short dropdowns stay as they were, because a search box over four things is
just something else to read.

> [!NOTE]
> This is only how the field looks. Underneath it is an ordinary dropdown with
> the same name, so what gets saved is exactly what would have been saved
> without it.

## The detail screen

Every column of one record, formatted: dates as dates, booleans as Yes or No,
related records by name rather than by id. Long text keeps its line breaks.

## The report

A printable version of the list, respecting whatever search and filters you had
applied. Use your browser's print command — the layout drops the menu, the top
bar and the buttons, and prints just the table.

## Deleting, and the alternative

The delete button asks first, and the confirmation names the record so you can
see what you are about to remove.

Often you do not want to delete at all — you want the record out of the way but
still there. That is archiving, and it is a separate chapter:
[Archiving](archiving).

## What each screen checks before it runs

Generated controllers are wired to the permission system. Someone whose role does
not include `books.edit` does not merely have the button hidden — the route
refuses them. The menu hides what they cannot reach, so they mostly never see a
403 at all.

See [Users and roles](users-and-roles).
